# ربط الهلال AI بقاعدة بيانات Firebase الدائمة

## ما الذي أصبح يُحفظ في Firestore؟
عند ضبط متغيرات Firebase Admin الثلاثة، يحفظ الموقع حسابات المستخدمين وأرصدتهم، وربط المتصفحات، والمشروعات، والمدفوعات، وأكواد الاسترداد، وطلبات الفيديوهات والنقاط الحمراء، وطلبات تغيير كلمة المرور في Firestore بدل ملفات JSON المحلية.

يظل Excel ملف استيراد/تصدير ونسخة مراجعة، وليس قاعدة البيانات التي يتصل بها الموقع أثناء التشغيل.

## إعداد Firebase مرة واحدة
1. افتح https://console.firebase.google.com/ وأنشئ مشروعًا جديدًا أو اختر مشروعك الحالي.
2. من القائمة الجانبية افتح **Build → Firestore Database** ثم **Create database**.
3. اختر وضع الإنتاج (Production mode) واختر أقرب موقع جغرافي متاح لك. لا تفتح قواعد Firestore للعامة؛ السيرفر يستخدم Firebase Admin SDK.
4. افتح **Project settings → Service accounts** ثم **Generate new private key**.
5. من ملف JSON الناتج خذ القيم التالية فقط إلى إعدادات الاستضافة (Render → الخدمة → Environment):
   - `project_id` إلى `FIREBASE_PROJECT_ID`
   - `client_email` إلى `FIREBASE_CLIENT_EMAIL`
   - `private_key` إلى `FIREBASE_PRIVATE_KEY`
6. احفظ المتغيرات ثم أعد نشر الخدمة. لا ترفع ملف المفتاح إلى GitHub ولا ترسله في محادثة عامة.
7. افتح `https://رابط-موقعك/api/health`. عند نجاح الاتصال يجب أن ترى `persistentStorage: true` و`databaseConnected: true`.

## ملاحظات مهمة
- لا يوجد اتصال فعلي بمشروعك حتى تضيف بيانات Service Account في Render؛ هذه الحزمة تجهز الكود لذلك ولا تحتوي على مفاتيحك السرية.
- البيانات الموجودة حاليًا في ملفات JSON القديمة لا تنتقل تلقائيًا إلى Firestore. يلزم تنفيذ ترحيل منفصل بعد أخذ نسخة احتياطية ومراجعة الحسابات لتجنب التكرار أو استبدال الأرصدة.
- كلمات المرور في ملف Excel لا تُستورد كنص صريح. الموقع يحفظ كلمات المرور بصيغة hash/salt.
- ملفات الفيديو نفسها ما زالت تُكتب على قرص الخادم، بينما بيانات طلب الفيديو أصبحت في Firestore. لاستمرارية ملفات الفيديو بعد إعادة النشر نحتاج ربط Firebase Storage أو قرص دائم منفصل.
- Firebase لديها حدود مجانية وحدود استخدام؛ راقب الاستهلاك من لوحة Usage and billing.
